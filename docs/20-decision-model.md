# 1. Executive Summary

This document defines the canonical representation of every Decision produced by MIOS. It builds upon the Intelligence Domain aggregates introduced in [17-domain-model.md](17-domain-model.md), the canonical Market Model defined in [18-market-model.md](18-market-model.md), and the canonical Analysis Model defined in [19-analysis-model.md](19-analysis-model.md).

This document becomes the single source of truth for all decision-support outputs generated by the Decision Engine, defined in [13-decision-engine.md](13-decision-engine.md).

MIOS does not generate trading signals. MIOS does not produce buy, sell, or hold recommendations. The Decision Model represents evidence synthesis and decision support only.

This document does not define algorithms, APIs, database schemas, events, or implementation classes. It defines the canonical model that future Technical Design documents must implement.

---

# 2. Scope

This document covers the canonical representation of:

- The Decision Assessment produced by the Decision Engine.
- The Decision Context surrounding a Decision.
- The Evidence Synthesis process by which a Decision combines upstream Assessments.
- The Confidence, lifecycle, states, traceability, and explainability requirements that apply to every Decision.

---

# 3. Design Principles

| Principle | Description |
|---|---|
| Single Source of Truth | Every Decision produced by the Decision Engine conforms to the same canonical structure. |
| Evidence First | No Decision is considered valid without references to the upstream Assessments and evidence that support it, consistent with [19-analysis-model.md](19-analysis-model.md). |
| Immutable Once Published | A published Decision is never modified; a change in market conditions produces a new Decision. |
| Explainability by Construction | The canonical shape of a Decision inherently carries the information needed to explain it. |
| No Instruction Content | A Decision never contains a buy, sell, or hold instruction, consistent with [01-product.md](01-product.md). |
| Synthesis, Not Creation | A Decision synthesizes existing upstream Assessments; it never introduces new market observations. |
| Traceable Confidence | Confidence expressed in a Decision is always traceable to the confidence and evidence of the Assessments it synthesizes. |
| Deterministic Identity | Every Decision has an identity that can be derived consistently and does not change once assigned. |

---

# 4. Decision Philosophy

- Decision ≠ Prediction. A Decision never forecasts future market behaviour.
- Decision ≠ Recommendation. A Decision never advises the trader to take a specific action.
- Decision ≠ Signal. A Decision never functions as a buy, sell, or hold trigger.
- Decision = Evidence-backed synthesis. A Decision is the coherent combination of already-produced, evidence-backed Assessments into a single decision-support view, leaving interpretation and action entirely to the trader, consistent with the "Trader Makes Every Decision" principle defined in [01-product.md](01-product.md).

# 5. Canonical Decision Object

| Attribute | Description |
|---|---|
| Decision Identifier | A unique identifier for the Decision instance. |
| Market | The Market the Decision pertains to, per the canonical Market Model in [18-market-model.md](18-market-model.md). |
| Instrument | The Instrument the Decision pertains to, where applicable. |
| Time Window | The point or span of time the Decision describes. |
| Supporting Assessments | References to the Liquidity, Options, Momentum, and Context Assessments synthesized by the Decision. |
| Contradiction Assessment | A reference to the Contradiction Assessment evaluating the Supporting Assessments, where available. |
| Evidence References | Pointers to the specific upstream evidence underlying the Decision, per [19-analysis-model.md](19-analysis-model.md). |
| Confidence | The Confidence associated with the Decision, per Section 8. |
| Context | The Decision Context surrounding the Decision, per Section 6. |
| Summary | A structured statement of what the Decision communicates, free of instruction content. |
| Generated Timestamp | The point in time the Decision was produced. |
| Engine Version | The version of the Decision Engine's synthesis logic, for traceability. |
| Status | The current Decision State, per Section 10. |
| Metadata | Supporting descriptive information relevant to interpreting the Decision. |
| Validation Rules | The Decision must satisfy the Validation Rules defined in Section 13 before being considered Valid. |

---

# 6. Decision Context

| Context Element | Description |
|---|---|
| Market Context | The relevant Context Assessment describing the broader market environment. |
| Session Context | The Trading Session, per [18-market-model.md](18-market-model.md), during which the Decision was generated. |
| Liquidity Context | The relevant Liquidity Assessment informing the Decision. |
| Momentum Context | The relevant Momentum Assessment informing the Decision. |
| Options Context | The relevant Options Assessment informing the Decision. |
| Contradiction Context | The relevant Contradiction Assessment describing agreement or conflict among the above. |
| Risk Context | Contextual factors relevant to the general uncertainty or risk conditions surrounding the Decision, expressed as evidence rather than as guidance. |
| Temporal Context | The Time Window and its position relative to recent Decisions for the same Instrument or Market. |

---

# 7. Evidence Synthesis

| Concept | Description |
|---|---|
| Supporting Evidence | Evidence from upstream Assessments that is consistent with, and reinforces, the Decision's Summary. |
| Conflicting Evidence | Evidence from upstream Assessments that is inconsistent with other evidence, as identified by the Contradiction Assessment. |
| Missing Evidence | Gaps identified where an upstream Assessment is unavailable or incomplete for the relevant Time Window. |
| Evidence Completeness | The degree to which all expected upstream Assessments are present and accounted for in the Decision. |
| Evidence Quality | The degree to which the referenced upstream evidence is timely, well-formed, and consistent with the canonical Analysis Model. |
| Evidence Consistency | The degree of agreement among the Supporting Assessments, as evaluated by the Contradiction Assessment. |
| Evidence Lineage | The traceable path from the Decision back through its Supporting Assessments to the underlying Market Model data. |

---

# 8. Decision Confidence

| Concept | Description |
|---|---|
| Confidence Meaning | Confidence describes the strength of the synthesized evidence behind a Decision; it never describes the likelihood of a future market outcome. |
| Confidence Boundaries | Confidence is expressed using the same qualitative scale defined in the Confidence Model in [19-analysis-model.md](19-analysis-model.md). |
| Confidence Inheritance | A Decision's Confidence is derived from the Confidence Levels of its Supporting Assessments and the findings of its Contradiction Assessment. |
| Unknown Confidence | A state indicating that insufficient upstream information exists to assign a Confidence Level to the Decision. |
| Unsupported Confidence | A state indicating that a Decision's claimed Confidence Level cannot be reconciled with its Supporting Assessments, which must be rejected under the Validation Rules in Section 13. |

No numerical scoring is used to express Decision Confidence.

---

# 9. Decision Lifecycle

| Stage | Description |
|---|---|
| Created | The Decision Engine has produced a Decision instance but has not yet confirmed it satisfies all Validation Rules. |
| Validated | The Decision has been confirmed to satisfy all Validation Rules defined in Section 13. |
| Published | The validated Decision has been made available to downstream consumers, including the AI Explanation Engine, and is now immutable. |
| Superseded | A newer Decision for the same Instrument or Market and a later Time Window has since been published. |
| Archived | The Decision is retained for historical reference but is no longer the subject of active downstream consumption. |

---

# 10. Decision States

| State | Description |
|---|---|
| Draft | The Decision has been created but not yet validated. |
| Valid | The Decision has satisfied all Validation Rules. |
| Published | The Decision has been made available to downstream consumers and is immutable. |
| Deprecated | The Decision remains published but has been superseded and should no longer inform new explanations. |
| Archived | The Decision is retained for historical or audit purposes only. |

---

# 11. Decision Traceability

Every Decision must preserve an unbroken chain of traceability:

- A Decision traces back to each of its Supporting Assessments.
- Each Supporting Assessment traces back to its own evidence, per [19-analysis-model.md](19-analysis-model.md).
- A Decision traces back to the Contradiction Assessment evaluating its Supporting Assessments, where available.
- The Explanation describing a Decision, per [14-ai-explanation-engine.md](14-ai-explanation-engine.md), traces back to that single Decision and, transitively, to every Assessment and evidence it references.

This traceability chain must remain intact and inspectable at every stage, consistent with the "Explain Everything" principle defined in [01-product.md](01-product.md).

---

# 12. Decision Explainability

Every Decision must be explainable.

Every statement within a Decision's Summary must be traceable to a Supporting Assessment or the Contradiction Assessment.

No hidden reasoning may contribute to a Decision.

The evidence chain from Decision to Supporting Assessments to underlying Market Model data must be preserved at all times.

---

# 13. Validation Rules

| Rule | Description |
|---|---|
| Supporting Assessments Mandatory | Every Decision must reference at least one Supporting Assessment. |
| Evidence Mandatory | Every Decision must carry Evidence References consistent with its Supporting Assessments. |
| Contradiction Assessment Optional Only When Unavailable | A Decision must reference a Contradiction Assessment whenever one exists for its Supporting Assessments; it may omit this reference only when no Contradiction Assessment has been produced. |
| Immutable After Publication | A Decision in the Published state is never modified. |
| Unique Identity | Every Decision must carry a unique Decision Identifier that does not change over its lifecycle. |
| Chronological Validity | A Decision's Generated Timestamp must be consistent with the Time Window and Supporting Assessments it references. |
| Engine Ownership | Every Decision must be attributable to the Decision Engine as its sole owner. |

---

# 14. Relationships

| From | To | Relationship |
|---|---|---|
| Decision | Assessments | A Decision references one or more Liquidity, Options, Momentum, or Context Assessments as Supporting Assessments. |
| Decision | Contradiction | A Decision references the Contradiction Assessment evaluating its Supporting Assessments, where available. |
| Decision | Explanation | A Decision is described by exactly one Explanation. |
| Decision | Instrument | A Decision is associated with the Instrument it pertains to, where applicable. |
| Decision | Market | A Decision is associated with the Market it pertains to. |

---

# 15. Domain Constraints

- No Buy instruction may appear in any Decision.
- No Sell instruction may appear in any Decision.
- No Hold instruction may appear in any Decision.
- No prediction of future market direction may appear in any Decision.
- Evidence is mandatory for every Decision.
- Explainability is mandatory: every Decision must be traceable to its Supporting Assessments and their evidence.
- Historical Decision instances are immutable once published.

# 18. ADR-001

**Decision:**
MIOS adopts a canonical decision model based on evidence synthesis, not prediction, recommendation, or signal generation.

**Reason:**
A canonical, evidence-synthesis-based decision model ensures that the Decision Engine's output remains strictly aligned with the "No Black Box Decisions" and "Trader Makes Every Decision" principles defined in [01-product.md](01-product.md). By defining the Decision as a structured combination of already-produced, evidence-backed Assessments, this model guarantees that every Decision remains traceable and explainable, and structurally incapable of carrying instruction content.

**Alternatives Considered:**

| Alternative | Reason Rejected |
|---|---|
| Model the Decision as a predictive probability of future price direction | Would directly contradict the "This is NOT a prediction system" principle defined in [01-product.md](01-product.md) and misrepresent evidence strength as forecasting certainty. |
| Model the Decision as a recommendation or signal (buy/sell/hold) | Would directly contradict the "This is NOT a signal provider" principle defined in [01-product.md](01-product.md) and remove the trader's role as the sole decision-maker. |
| Allow the Decision Engine to define its own ad hoc output structure per release | Would risk inconsistent representation of evidence synthesis over time, undermining the AI Explanation Engine's ability to reliably explain every Decision. |

**Consequences:**

- The Decision Engine must produce output conforming to the Canonical Decision Object defined in Section 5.
- The AI Explanation Engine can rely on a consistent, well-defined Decision structure when generating explanations.
- Any future algorithm, API, or event contract for decision-support must preserve the evidence-synthesis nature of this model and must never introduce instruction content.

# 20. Glossary

| Term | Meaning |
|------|---------|
| Decision | The canonical, evidence-synthesized decision-support output produced by the Decision Engine. |
| Decision Context | The surrounding market, session, and cross-engine information relevant to interpreting a Decision. |
| Evidence Synthesis | The process of combining upstream Assessments and their evidence into a single, coherent Decision. |
| Supporting Assessment | An upstream Liquidity, Options, Momentum, or Context Assessment referenced by a Decision. |
| Contradiction Assessment | The evaluated relationship among Supporting Assessments referenced by a Decision, per [12-contradiction-engine.md](12-contradiction-engine.md). |
| Confidence | A qualitative indication of how strongly synthesized evidence supports a Decision. |
| Traceability | The property of a Decision being consistently linked back to its Supporting Assessments and their evidence. |
| Explainability | The property of a Decision being fully describable in terms of the evidence and Assessments that produced it. |
